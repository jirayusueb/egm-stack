### Prototype

**You own the decision, not the code. The prototype is throwaway.**

Read first: the `the-pragmatic-programmer` rule pack.

1. Frame the fork the prototype must settle. Name the question, the options, and the evidence that would decide it. If no decision is at stake, route to the feature playbook.
2. Timebox the work. Name the stop point before the first line. Speed over polish, and code quality does not count here.
3. Build the smallest sketch that answers the question. Use **arena** when two or more designs need the same evidence.
4. Decide from what you observed. A render, a timing, an output, or a user reaction.
5. Record the decision and the scratch location. Hand the chosen direction to the feature playbook for the real build.

**Reply:** the fork, the options, the evidence, the decision, and the scratch path. Say plainly that the prototype is throwaway.
