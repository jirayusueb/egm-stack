# 05 DDD and book rules

This note records why the stack ships one `rules` skill with fourteen book packs, and how the `ddd` skill uses three of them. It covers what we vendored, what we wrote, and the license terms.

## What agent-rules-books is

[ciembor/agent-rules-books](https://github.com/ciembor/agent-rules-books) is a MIT-licensed collection of rule packs distilled from classic software engineering books. The author is Maciej Ciemborowicz. The README labels the release v0.6. We pinned commit `893a88a6fce3a80c565bf39ac65021b43a8b2990` from 2026-09-10.

Each book directory holds four files. A `SKILL.md` entrypoint sits beside three rule sets. The `full` file is the canonical reference. The `mini` file is the recommended version for real task use. The `nano` file is a compact fallback for tight context budgets. The upstream README publishes lines and rule counts for each variant.

Upstream also ships a skill install path. A user can run `npx skills add ciembor/agent-rules-books --all`, list skills, or install one book by name.

## What we vendored

We vendor the `mini` packs only. The stack ships fourteen files at `skills/rules/references/<book>.md`. Each file starts with a header. The header carries the source URL, the pinned commit, the MIT notice, and the line "condensed; verify against the book". We retitle each pack as `OBEY <Book> by <Author>` and keep it under eighty lines. We do not vendor `full` or `nano` files. `skills/rules/references/index.md` is generated by the build, so it cannot drift from the directory.

The `rules` skill loads a pack on demand. It selects one pack for the task and does not load all fourteen. The rationale is context economy. A mini pack costs about five hundred tokens, and a full pack costs many times more.

## What we synthesized

The book rules describe a domain. They do not run a modeling session. We wrote four things that the packs do not contain.

1. `skills/ddd/SKILL.md` runs a strategic pass, then a tactical pass, then a scored handoff. It states each decision and points to a pack for the rule.
2. `skills/ddd/references/rubric.md` holds twelve checks with one question and one fail signal each. Six checks are strategic and six are tactical. The pack rules inform the checks. The wording and the severity mapping are ours.
3. `resources/document_standards/domain-model-standard.md` is our review standard for the `ddd` profile. It is not copied from a pack.
4. The `ddd-model`, `ddd-review`, and `ddd-modernize` playbooks under `skills/egm-mode/playbooks/` decide which packs and which skills run for each job.

## How the DDD packs are used

The `ddd` skill reads one pack per pass. The Domain-Driven Design pack covers strategic design, context mapping, and distillation. The Distilled pack covers the smallest effective practice and the subdomain classes. The Implementing pack covers aggregates in code, domain events, application services, and integration.

The playbooks map the packs to jobs. `ddd-model` reads the first two packs and then drafts. `ddd-review` reads Distilled and Implementing, then runs `egm-review` with profile `ddd`. `ddd-modernize` reads Implementing and Working Effectively with Legacy Code, then moves one seam at a time.

The model artifact is `.egm/<slug>/domain_model.md`. A review report is `.egm/<slug>/ddd_review.md`. An approved spec is promoted to `docs/designs/<slug>.md`.

We choose DDD only when complexity justifies it. A simple CRUD service does not need three packs. The Distilled pack makes the same point, and the `ddd` skill repeats it as a when-not-to-use rule.

## Licensing and attribution

The upstream repository is MIT licensed. The copyright line is `Copyright (c) 2026 Maciej Ciemborowicz`. MIT permits redistribution and adaptation when the notice travels with the copy. Our `NOTICE` names the project, the author, and the license. `UPSTREAM.md` pins the commit and lists the vendored files. Each vendored file repeats the attribution in its header.

The books themselves are not redistributed. The packs are the upstream author's distilled prose, not excerpts. We add no book text, no chapter summaries, and no figures. A reader who needs authority checks the book. This is why every pack header says to verify against the book.

The Apache-2.0 outbound license covers our skill bodies, the rubric, and the standards. The vendored packs remain MIT. The two licenses are compatible for this use. We keep the MIT notice in each vendored file rather than relicensing the text.

## Limits

- A mini pack is condensed. It omits edge cases and disagreements between editions.
- The packs are advice. Our rubric supplies the pass and fail decision.
- The line budget caps detail. When a task needs more, read the book.
- Rule packs age. The pinned commit is the contract. Refresh it in a reviewed change.
- Our reading of the packs is **Verified** against the pinned commit. Our claims about the books are **Reported** from those packs. We did not read the full books.
