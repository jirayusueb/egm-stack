# 08 STE100

`ste100` is controlled language for procedures and safety text. It paraphrases
publicly documented ASD-STE100 constraints. The official specification and its
dictionary are not redistributed here. Conformance needs the official copy.

## When to use it

Use `ste100` when a reader must follow text exactly and must not misread it.

- Runbooks and rollback steps.
- Safety warnings and irreversible actions.
- Error messages a person acts on.
- Installation and recovery procedures.

Do not use it for a design rationale, a review report, or a PR body. Those are
explanation, not procedure. `technical-writing` owns them.

## The order

Three skills split the work and never duplicate a rule.

1. `unslop` removes AI tells. It uses a stable id space up to 33, with the upstream gaps preserved.
2. `ste100` applies controlled language after the text is clean.
3. `technical-writing` owns structure and voice for explanation.

Run `unslop` first. Clean the prose, then constrain it. A constrained sentence
built on a slop sentence is still slop.

## What the linter checks

The `ste100` linter is heuristic. It reports findings with a rule id and a line
number. It checks categories like these.

- One instruction per sentence.
- Sentence length within the limit.
- Active voice for instructions.
- A verb for an action, not a noun form.
- No dangling modifier at the start of a sentence.
- Articles kept where a reader needs them.
- Consistent term for one thing.
- No ambiguous pronoun.

The linter is a first pass. A clean report is not a certification. A human
still signs off on safety text.

## Report

A run writes `ste100_report.md` under the run directory. Each row names the
file, the line, the rule id, the finding, and the suggested rewrite.

```text
ste100_report.md
  docs/runbook.md:14  STE-VERB   "perform the restart" -> "restart the service"
  docs/runbook.md:22  STE-LEN    sentence is 34 words, limit is 20
```

## The fix loop

1. Run `ste100` on the target text.
2. Fix the findings that change meaning or risk.
3. Rerun. Stop when the report is clean or the remaining rows are accepted with
   a reason.
4. Keep the final report beside the change.

## Limits

- The linter tests patterns, not understanding. It cannot see a wrong
  instruction.
- Paraphrased constraints can miss a nuance of the official standard.
- A safety-critical procedure needs a human owner, not only a tool.

## Example

Before.

```text
It is important that the operator should be aware that a restart of the
service may be required in the event that the connection is lost.
```

After.

```text
If the connection is lost, restart the service.
```

One instruction. Active voice. One sentence. The reader acts.
